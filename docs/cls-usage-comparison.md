# CLS 使用方式：当前项目 vs 企业项目

> 本文对比腾讯云日志服务（CLS）在两类场景下的使用方式：一类是当前项目（AI 运维 Agent demo）对 CLS 的消费方式，另一类是常规企业项目的完整使用方式。用于厘清日志平台在可观测性体系中的定位与职责边界。

---

## 1. CLS 的定位

CLS（腾讯云日志服务）是云上的统一日志平台：所有服务的日志（应用日志、中间件日志、容器/k8s 日志、云产品审计日志、负载均衡访问日志等）统一汇聚到 CLS，作为「可搜索、可分析、可告警、可归档」的日志事实源。

在可观测性体系中，它与指标、链路构成三大支柱：

| 支柱 | 职责 | 典型产品 |
|---|---|---|
| Metrics 指标 | 数值型时序（CPU、QPS、延迟），用于趋势与告警 | Prometheus / 云监控 |
| Logs 日志 | 非结构化文本、事件详情，用于排查根因 | CLS / ELK |
| Traces 链路 | 单次请求的调用链路，用于定位调用关系 | APM |

## 2. 企业项目使用 CLS 的完整生命周期

### 2.1 采集（Collect）
- 服务器 / 容器上部署 **LogListener** 采集 agent，读取文件 / stdout，批量上传至 CLS。
- 应用内嵌 SDK / API（`PutLogs`）直接上报结构化日志。
- 云产品一键接入（k8s 审计、LB 访问日志、云函数日志等）。

### 2.2 存储与索引（Store & Index）
- 按 `日志集（logset）→ 日志主题（logtopic）` 两级组织（对应 CLS 的 `DescribeTopics` / `DescribeLogsets` 管理接口）。
- 配置索引：全文索引 / 键值索引，决定哪些字段可被检索与 SQL 聚合。
- 设置保留时长、热/温/冷分层与压缩。

### 2.3 检索与分析（Query & Analyze）
- 通过控制台 / API 使用 **CQL + SQL** 检索，支持聚合、分组、JSON 解析与图表。
- 对应 CLS 的 `SearchLog`、`DescribeLogHistogram`、`GetLogs` 等接口。

### 2.4 告警（Alarm）
- CLS 提供**日志告警**：定时执行检索语句，命中条件（错误率突增、关键字出现 N 次等）即触发。
- 通知渠道：邮件、企业微信 / 钉钉 webhook、短信。
- 企业告警通常分两类并存：**指标告警**（Prometheus / 云监控）与**日志告警**（CLS）。

### 2.5 投递与归档（Ship）
- 长期日志投递至 COS / Kafka / ES，供数仓、审计、离线分析使用。

### 2.6 可视化
- 基于检索结果构建 Dashboard。

## 3. 企业 AIOps 对 CLS 的消费方式

- 企业主链路（应用 → 日志 → 告警 → 工单）对接 CLS 使用**官方 SDK / REST API**：写入走 `PutLogs`，读取走 `SearchLog`、`GetLogs`、`DescribeAlarms` 等。
- **MCP** 是 AI Agent 场景下的工具调用协议：当需要让大模型 Agent 动态查询日志时，才将 CLS 能力封装为 MCP 工具暴露给 Agent。企业主链路不经过 MCP。

---

## 4. 当前项目与完整形态的差异

| 环节 | 当前项目 | 企业项目 |
|---|---|---|
| 采集 | 无（日志以 mock / 本地数据演示） | LogListener / SDK 将日志写入 CLS |
| 存储检索 | 通过 MCP 只读检索 CLS | CLS 统一平台（采集、索引、检索一体） |
| 告警 | 仅 Prometheus（无环境时 mock 兜底） | Prometheus 指标告警 + CLS 日志告警 + Alertmanager + 值班联动 |
| 消费方式 | MCP（Agent 专用） | 官方 SDK / REST API |
| 联动 | 单次分析报告，写回会话记忆 | 告警 → on-call → 工单 → 根因分析 |

---

## 5. 职责边界说明

- 当前项目聚焦「**AI 运维 Agent 如何消费日志做根因分析**」这一下游场景：通过 MCP 协议把 CLS 的检索能力暴露给 Agent，让模型按需查询日志佐证根因。
- 告警仍走 Prometheus 体系，体现「监控告警」与「日志检索」的分工：告警来源为 Prometheus，日志来源为 CLS，两者为两条独立数据链路，在分析报告中由 Agent 汇总。
- 采集、CLS 日志告警、告警联动、投递归档属于上游 / 平台层职责，不在当前项目范围内；上述架构形态为标准的可观测性组织方式。
